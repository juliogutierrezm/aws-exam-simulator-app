# AWS SAA App

Angular-based study tool for the **AWS Certified Solutions Architect – Associate** exam.

## Purpose

Practice AWS SAA questions, simulate timed exams, review mistakes, and explore AWS service icons
across 455 questions spanning 8 practice exams.

Fase 1 funciona completamente en frontend, sin backend, autenticación ni sincronización cloud.

## Installation

```bash
git clone <repo-url>
cd aws-saa-app
npm install
```

---

## Development

```bash
npm run dev
```

This command:
1. Validates `data/` (520 questions, structure checks)
2. Audits `resources/aws-icons/` (302 SVGs)
3. Builds the icon manifest (`public/data/aws-icon-manifest.json`)
4. Generates an optimized runtime dataset and syncs data → `public/data/`
5. Syncs required SVGs → `public/aws-icons/`
6. Starts the Angular dev server at `http://localhost:4200`

---

## Build (production)

```bash
npm run build
```

Runs the same preparation pipeline, then compiles Angular for production into `dist/`.

---

## Tests

```bash
npm test
```

Runs Angular unit tests (Karma + Jasmine) in headless Chrome. Covers:
- Dataset loading
- Icon key resolution
- Fallback for unknown/missing icons
- HTTP error handling
- Quiz generation and primary-service filters
- Exact-match evaluation for multi-select answers
- Persistent sessions, results, timer restoration, and themes

## Fase 1 routes

- `/` — Home and local progress summary
- `/practice` — Practice builder, including random and service filters
- `/practice/session` — Shared practice question engine with feedback
- `/exam` — Timed exam builder (65 questions / 130 minutes by default)
- `/exam/session` — Exam engine without answer disclosure
- `/results` — Score and session summary
- `/review` — Deterministic review from persisted result data
- `/services` — AWS service explorer and practice entry point
- `/dev/icons` — Technical icon gallery retained from Fase 0

Active sessions and the last 20 results are stored locally under versioned keys. Session question IDs
are generated once, persisted immediately, and never regenerated on refresh or restore. Results retain
the IDs, responses, classification, configuration, timestamps, duration, and dataset version `2.3`.

## Data sources

### `data/` vs `resources/` vs `public/`

| Directory | Role | Edit? |
|-----------|------|-------|
| `data/` | **Canonical source** — the authoritative dataset | No — frozen at v2.3 |
| `resources/aws-icons/` | **Canonical SVG source** — original AWS icons | No — add/replace only |
| `public/data/` | Runtime copy — regenerated by `sync:data` | No — generated |
| `public/aws-icons/` | Runtime SVGs — regenerated by `sync:icons` | No — generated |

---

## Updating the dataset

> ⚠️ The dataset is frozen at **v2.3**. Do not modify existing questions.

If a future version is introduced:
1. Replace the files in `data/` with the new dataset.
2. Run `npm run audit:data` to validate.
3. If validation passes, run `npm run prepare:app` to regenerate runtime assets.

---

## Adding or correcting an icon mapping

1. Place the SVG in the appropriate category subdirectory under `resources/aws-icons/`.
2. Open `scripts/build-manifest.js` and add/fix the entry in the `MANUAL_ALIASES` table:
   ```js
   'my-icon-key': 'Category/My-Service.svg',
   ```
3. Run `npm run build:manifest` to regenerate manifests.
4. Run `npm run sync:icons` to copy the new SVG to `public/aws-icons/`.
5. Verify `docs/audits/aws-icon-audit-report.json` — `missing_icon_keys` should decrease.

## Known limitations (Fase 1)

- `amazon-quicksight` has no matching SVG in the icon pack — shows the fallback placeholder.
- Correct answers are available in the frontend runtime by design; backend answer-key separation is deferred.
- Bookmarks, accounts, cloud sync, Cognito, payments, and leaderboard are outside this phase.
